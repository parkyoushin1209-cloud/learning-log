verilog PLI루틴을 사용해 c루틴과 통신 가능했음, TF(task/function), ACC(access), VPI(verification procedural interface)를 이용해 지연 계산기 생성 및 여러 시뮬레이터와 연결/동기화 가능
문제점 => PLI를 이용해 간단한 C루틴과 연결을 원할때라도 많은 코드 작성 필요 및 많은 개념 이해가 필요했음 + 베릴로그 데이터 구조 붕괴 방지를 위해 verilog, c 사이의 데이터 복사가 필요했고 이는 시뮬레이션 오버헤드 증가로 이어짐
c코드는 프로세서 같은 시뮬레이션 모델을 포함하고 있을 수도 있으며 이는 verilog 모델과 나란히 인스턴스화됨 또는 베릴로그 모델과 트랜잭션, 사이클 수준에서 비교되는 레퍼런스 모델이 될 수 있음

1-1. passing simple values       (import 선언의 의미)
import -> sv루틴이 외부언어에 구현돼있음을 선언    DPI-C -> DPI루틴임을 명시   나머지 -> 루틴 인자 묘사함

1-2 the import declaration        (범위, 함수 타입)
import 선언은 c 태스크 또는 함수의 프로토타입을 정의하나 sv의 타입을 사용한다.
c 반환 있는 함수 -> sv function   void c 함수 -> sv 태스크 또는 void 함수
c함수명이 sv의 예약된 키워드명과 같다면 명칭 바꾸시 c함수명은 글로벌심볼, sv함수명은 로컬 심볼
sv는 루틴 오버라이딩 지원 안 함(같은 함수명으로 int, real 이런식으로 여러번 쓰는 것)
루틴 선언 가능한 sv 코드 어디서나 import 가능함
import 선언은 선언된 곳에서 지역 요소가 되므로 여러번 사용할 거면 package 내부에 두기(import문의 변화는 package에만 국한됨

1-3. argument directions           (인자 개수, 방향, 타입)
imported C routine은 0 개 이상의 인자를 가질 수 있음
기본적으로 방향은 input이나 output/inout도 가능함(ref는 불가능)
integer, real number 등 간단한 값이나 void일 수 있음
input 인자에는 const를 사용해 버그 확률 줄일 수 있음

1-4 argument type      (타입 매핑, 더 큰 비트로의 변환, 함수 결과 값)
sv type이 c의 input 또는 output으로 매핑되는 타입이 존재함
몇몇 매핑은 정확하지 않을 수 있음 svBit는 최종적으로 unsigned char로 매핑 이는 8비트이므로 7~1비트가 의미없는 값일 수 있다 -> mask off적용
c 구조체들은 svdpi.h에 정의돼있음
LRM은 imported 함수 결과를 작은 값으로 제한함(void, byte, shortint, int, longint, real, short real, chandle, string, bit/logic타입 싱글 비트 값) 벡터는 불가능

1-5 importing a math library routine     (math.h)
c의 math.h의 여러 많은 함수를 가져올 수 있음 => 작성해야 할 코드가 줄어듦
import "DPI-C" function real fabs(input real r);

2-1 a counter with static storage 
매핑되는 sv DPI type이 있다면 일반 c타입보다 DPI 타입 사용이 좋음
const로 포인터 전달 시 근본적인 값은 바꿀 수 있으나 포인터가 가리키는 대상 자체는 변경 불가
7비트 값이 8비트에 저장되는 경우 msb mask off

2-2 the chandle data type (chandle 사용 이유)
c/c++의 포인터를 담을 수 있도록 충분히 크기가 크다.
c의 함수 안에 static 변수가 있어 c code를 호출하는 여러 모듈이 존재한다면 하나의 변수를 여럿이서 사용하게 된다. => 저장공간을 할당한 후 input/output 신호와 그것을 가리키는 핸들을 전달하기

2-3 representation of packed values(2-상태 값을 표현하는 방식)
"DPI-C" 문자열은 packed value의 정형화된  표현방식을 사용할 것임을 명시함 32bit씩 하나의 요소에 담음 이때 최상위 비트 마스크 처리 하기

2-4 4-state values( 4상태 변수의 최하의 비트 특징)
4-state 변수 저장시 LSB 비트에 aval, 바로 위 비트에 bval로 알려진 두 개의 bit를 사용함 0 => 00 / 1=>01 / z=>10 / x=>11 실질적인 값은 최하위 2개 비트의 값을 빼고 생각
logic은 unsiged char에 logic[0:0] svLogicVecVal로 매핑됨(주의)
c 코드에서 함수를 깔끔하게 종료시키고 싶다면 vpi_control(vpiFinish,0) 사용 vpi_user.h 에 정의 돼 있음

2-5 converting from 2-state to 4-state (전환하려면 어떤걸 수정?)
sv에서 bit를 logic으로 수정 및 4상대 값 사용(logic, integer) 등
c에서 매핑되는 변수 타입 사용 (svBitVecVal => svLogicVecVal로 그 인자에 대한 참조는 정확한 데이터 접근을 위해 .aval을 사용해야 할 것)
  4상태 변수로부터 값을 읽을 때는 x,z인지 확인하기 위해 bval bit check (x,z만 최상의 비트가 1임 &0x2 사용해서 확인)
4상태 변수에 쓸 때는 z,x 값을 쓸 필요가 없는 한 bval 클리어
