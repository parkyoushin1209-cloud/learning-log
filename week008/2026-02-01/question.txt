1. Compile, elaboration, run time의 순서와 각 시간별 하는 일이 무언인가?
순서는 compile -> elaboration -> run time 순서임
Compile time (컴파일 타임)
소스 코드를 문법적으로 해석하고 번역하는 단계/ 문법 체크, 타입 & 비트폭 결정, 클래스&모듈&커버그룹 정의 파악, bin 이름&구조가 정적으로 확정됨(문법 및 구조 확정)
못 하는 것 => 값을 계산해 bin 생성, 동적 bin 이름 생성, 신호 값 참조

Elaboration time (엘라보레이션 타임)
컴파일된 설계를 실제로 인스턴스화하는 단계, 시뮬레이션 시작 직전/ 모듈 인스턴스 생성, 커버그룹 인스턴스 생성, 파라미터 값 확정, generate문 펼침, 크로스 커버리지 구조 확정
확정되는 것 => 커버그룹 인스턴스 개수, 객체별 옵션 적용 여부, auto_bin 개수 결정(인스턴스 생성)

Runtime (Simulation time)
시뮬레이션이 실제로 시간을 흘리며 동작하는 단계/클럭 토글, 신호 값 변화, 커버그룹 샘플 메서드 호출, bin hit 카운트 증가, 커버리지 누적
이때 일어나는 것 => 어떤 bin이 hit 됐는가, 몇 번 hit 됐는가, transition sequence 매칭 여부

2. bin이 생성되는 순서는 어떻게 되는가?
-명시적으로 정의한 bins 생성 -> (있으면) default bin 생성, ignore_bins/illegal_bins 규칙 적용
=> ignore, illegal은 커버리지 계산에 무시되긴 하나 생성이 아예 안되는 것은 아님

3. 리셋일때 커버리지 수집을 안 하는 이유는 무엇인가?
리셋은 설계가 초기화되는 과정, 레지스터, 플립플롭, 상태머신 등 값이 강제로 0 또는 초기값으로 세팅됨
=> 의미 없고 단순히 초기화만 하는 과정임
커버리지 왜곡 방지 => reset 동안 샘플링하면 대부분 값이 0임, 크로스 커버리지 등에서 많은 bin이 hit 되지 않은 것처럼 계산됨
실제 기능 검증 커버리지와 혼동됨 => 실제 관심 있는 동작이 아님(검증 목표는 리셋 후 정상 동작 시나리오 but reset은 기능이 아니라 설계 준비 단계)
