메모리의 주소, 포인터: 
포인터는 메모리의 주소를 가리킴 int* ptr = &value 형식으로 사용 
*ptr은 포인터가 가리키는 객체의 값을 의미함
타입 변환은 불가능 (int* - char* 사이 변화 등)


sizeof 연산자
메모리의 크기를 반환함(byte 단위)
임베디드 시스템, c++ 등 여러 시스템에서 사이즈는 다를 수 있음


자유 저장 영역과 포인터
컴파일러는 코드 저장영역, 정적 저장 영역, 스택 저장 영역을 미리 할당한 후 남은 공간을 자유 저장 공간으로 활용(힙 영역)
자유 저장 공간은 런타임 때 필요에 따라 할당하고 사용할 수 있음
new연산자를 사용해서 할당 가능


포인터를 이용한 접근
포인터를 이용한 접근을 위해서는 *, [ ]를 사용 가능함


구간
런타임때 new double[n] 처럼 new를 사용해 포인터를 반환해줄 경우 포인터는 몇 개의 요소만큼 할당됐는지는 알 수 없음
그렇기에 다른 메모리 공간에 덮어쓰는 등의 일이 발생할 수 있음
ex. double* ptr = new double[3]; 일때 ptr[-3] = value를 해버리면 잘못된 공간에 덮어쓰기 가능


초기화(기본 생성자 유무)
클래스의 경우 기본 생성자가 있는 경우 클래스 타입 X에 대하여 X* p = new X; 처럼 포인터를 반환해줘도 문제가 없으나
기본 생성자가 없는 경우 Y* q = new Y처럼 사용할 수 없음(오류)


널포인터
포인터에 부여할 포인터가 없다면 nullptr 사용 가능
포인터의 유효성을 확인할 때도 if(ptr != nullptr) 처럼 사용 가능 (ptr이 0이 아닌 임의의 값을 갖거나 delete된 객체를 가리키고 있을 수도
있으므로 완벽한 방식은 아님)
nullptr을 대입하면 0이 대입되므로 if(ptr)로도 확인 가능


자유저장 영역 해제
자유저장 영역을 해제해 주지 않는다면 메모리 누수가 발생할 수 있음
=> delete 사용 delete p, delete[] p 형식으로 사용 가능하며 후자는 new로 할당한 객체의 배열을 해제함


소멸자
소멸자는 유효범위를 벗어날 경우 암묵적으로 호출됨


자동으로 만들어지는 소멸자
클래스 내부에 데이터 멤버가 소멸자를 가지고 있을 경우 포함하는 클래스 소멸 시 내부 데이터들도 같이 소멸됨


소멸자와 자유 저장 영역
생성자를 호출할 경우 클래스 내부 데이터멤버의 생성자도 같이 호출되며 소멸자도 마찬가지로 작동함
1. virtual 함수를 포함하는 클래스는 보통 기반 클래스로 쓰임
2. 기반클래스라면 파생 클래스를 new로 생성 가능
3. 이후 기반 클래스 타입의 포인터로 조작할 경우 기반 클래스의 delete을 실행할 확률이 높음 소멸자를 virtual로 해야
서브 클래스의 소멸자까지도 안전하게 호출 가능함


요소에 접근
duoble* elem 에 대해 new로 여러 개의 double을 할당한 후 elem[n]으로 접근 가능함


클래스(벡터) 객체를 가리키는 포인터 new, delete 할 경우 발생 이벤트

vector* p = new vector(s)를 호출한 경우 
벡터를 위한 메모리 공간 할당 -> 벡터의 생성자 호출 -> 각 요소에 대해 메모리 할당 후 모든 요소 초기화
delete q를 호출한 경우
벡터의 소멸자 호출 -> 각 요소에 대해 소멸자가 있다면 호출 -> 요소의 메모리 해제 -> 벡터의 메모리 해제


타입 다루기(void*, cast)
로우레벨 연산(초기화, 대입, *, [])에서 c++은 약간의 편의 구문과 타입 시스템을 바탕으로 컴파일 시점의 타입 일관성을 제공함
최소한의 보호 장치(타입 시스템의 보호)를 포기해야할 경우 다음의 겻이 필요함
1. 메모리에 존재하는 객체의 타입에 상관 없이 그 객체를 가리킬 수 있는 포인터(void*)
2. 그러한 포인터가 가리키는 메모리를 컴파일러가 (증명되지 않은) 특정 타입으로 간주하게 하는 연산


포인터와 참조(차이점)

1. 포인터에 대한 대입은(가리키는 객체의 값의 아니라) 포인터의 값을 변경
2. 포인터를 얻으려면 new나 &를 사용
3. 포인터가 가리키는 객체에 접근하려면 [ ] 나 * 사용
4. 참조에 대한 대입은(참조 자신이 아니라) 가리키는 객체의 값을 변경
5. 참조를 초기화한 후 다른 객체를 가리키게할 수 없음
6. 참조를 대입하면 깊은 복사(가리키는 객체에)를 수행하며 포인터를 대입하면 그렇지 않다(포인터 자체의 값에 대입)
7. 널 포인터의 유무


포인터 매개변수와 참조 매개변수(값을 수정할 때 어떤 거 고를지)
작은 객체의 경우 => 값에 의한 전달 사용
(nullptr로 표현되는)객체 없음이 합당한 함수 => 포인터 매개변수 + if, nullptr로 유효성 확인(널포인터면 에러)

포인터와 참조 상속
공개 기반 클래스의 경우 subclass*를 superclass*로 암묵적 변환이 가능함
=> 함수의 매개변수에 super, main에서 인자로 넣을 때 sub 대입 가능
