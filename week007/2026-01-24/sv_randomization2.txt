좋은 랜덤화 기술 = 랜덤 스티뮬러스의 유효함을 보장하는 여러 제약을 생성하는 것(valid constraint로 알려짐)
에러 생성을 원하면 constraint_mode 사용하기 제약 이름은 특징을 드러내게 valid_~~형식

in line constraint => randomize() with{제약 조건}
추가 제약과 기존 제약이 충돌할 경우 constraint_mode 사용

randomize 호출 시 pre_randomize() -> constraint solver -> post_randomize() 순으로
일반 함수와 같이 클래스 안에 정의하며 randomize와의 순서에 맞춰 실행되는 특별한 함수로 볼 수 있음
void 함수로 테스크 호출은 불가능 확장된 클래스에서 base 클래스의 함수 기능 필요시 super.함수명으로 호출
두 함수는 시간을 포함할 수 없으므로 randomize에 시간을 사용하면 안됨

randomnumber 함수
$random: 균등 분포, 32비트 signed 랜덤 값 반화  $urandom: 균등 분포, 부호 없는 32비트 랜덤 값 반환 $dist_uniform: 균등 분포
$urandom_range: 범위 내 균등 분포 인자가 하나면 0~ 인자까지 $dist_exponential : 지수적 감수 분포  $dist_normal: 종형 분포  $dist_poisson: 종형 분포

constraints tips and techniques
1. 변수를 가진 제약 변수 값만 변경해 조건 변경 가능
2. nonrandom 값 사용 rand_mode로 rand, randc를 끄고 킬 수 있음
3. 제약을 사용해 값 확인: 모든 변수가 유효한지 확인하려면 handle.randomize(null) 사용 null 대신 논랜덤 변수를 입력해도 결과는 같음
4. 개개의 변수 랜덤화: 랜덤화할 변수만 randomize()의 인자로 넣어줌
5. 제약 온오프: 개개의 제약을 꺼 에러를 생성하는 건 괞찮으나 남용하지 않아야 함
6. in line 제약을 사용해 test에서 제약 명시: 많은 경우 제약은 하나의 테스트에서만 사용되므로 in line 제약 사용 가능
in line 제약의 트레이드 오프
-여러 장소에 있는 새 제약이 모든 활성화도니 제약 이해에 어려움을 줄 수 있음(클래스에 제약 추가 시 서로 충돌 가능)
-여러 테스테에서 재사용이 힘들어짐(분리된 파일의 루틴에 두고 필요시 호출 가능) external constraint와 비슷
7. 테스트 내 제약을 external 제약을 이용해 명시
제약 본체는 클래스 내에 정의될 필요는 없다. 각 테스트에서 자신만의 제약 정의 가능
-이 제약은 파일 안에 둘 수 있고 테스트에서 재사용도 가능하다. 이 때 패키지 내에 정의된 클래스는 또한 같은 패키지에 정의된 external constraints를 가져야해 패키지의 이점이 사라질 수 있다.
-존재하는 제약을 변경하는 것이 아니라 추가하는 것임
8. 클래스 확장: 확장된 클래스와 베이스 클래스에서 같은 이름으로 정의돼있는 경우 확장된 클래스가 대신함

흔한 랜덤화 문제
1. 부호있는 변수는 주의를 반드시 필요한 경우에만 사용
2. solver performance tip
-raw data로 배열을 채우기만 할 때 solver를 사용하는 대신 pre_randomize() + ($urandom/$unrandom_range)를 사용해라 훨씬 빠르다.
값의 범위가 균등하지 않거나 간단한 관계를 가질 때에도 if문을 사용하면 될것이다.
3. 효율성을 높이기 위해 올바른 연산자를 사용해라
-덧셈, 뺄셈, 비트 추출, 시프트 등 간단한 산술 연산은 solver에 의해 매우 효율적으로 다뤄짐
-곱셈, 나눗셈, 나머지는 32bit값으로 매우 비싸다
많은 하드웨어 내 상수는 2의 거듭제곱으로 돼있으므로 모듈로,나눗셈 연산은 비트 추출을 활용 가능 곱셈의 경우는 시프트로 처리

반복적인 배열 제약
1. 배열 크기 d.size() inside {[lo:hi]} 형식 사용
2. 각각의 배열과 배열 요소 제약
constraint c_len {foreach(len[i]) len[i] inside {[1:255]}; len.sum() <1024; len.size() inside {[1:8]}; 등과 같이 제약 걸 수 있음
3. 고유 값을 가지는 배열 생성 (참조 코드 확인)
4. 핸들의 배열 랜덤화
다른 배열과 다르게 각 요소를 먼저 할당해 준 뒤 램덤화 (random solver는 객체를 생성하지 못한다.)
다이나믹 배열의 경우 필요한 요소의 최대 수만큼 할당 후 제약을 사용해 사이즈를 조정한다.(유지, 감소만 가능하며 추가는 못함)
