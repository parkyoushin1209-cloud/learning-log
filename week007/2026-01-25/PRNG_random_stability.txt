PseudoRandom Number Generator(PRNG)= 수도 난수 발생기
베릴로그에서는 단일 PRNG를 사용하며 다음 상태를 구하기 위해 현재 상태의 제곱을 취해 중간 비트를 더하고 현재 상태와 더함

//verilog PRNG
bit [31:0] state;
function bit[31:0] my_random();
bit [63:0] s64;
s64 = state * state;
state = (s64 >> 16) + state;
return state;
endfunction

랜덤 안정성 - 여러 발생기
발생기가 하나일 경우 객체를 1개 가지는 a, 객체를 2개 가지는 b 랜덤화 할 경우와 2,2개 가질때 랜덤화할 때와 부여되는 값이 다름 
(a.1, b.1, b.2) = (1,2,3) (4,5,6) / (a.1, a.2, b.1, b.2) = (1, 2, 3, 4) (5,6,7,8) 처럼 즉 a가 b에도 영향을 미치는 상황이 되며 이 상황은 다음과 같은 문제를 가짐
1. 테스트 재현성 문제: 같은 테스트를 다시 돌렸는데 결과가 달라질 수 있음
2. 시나리오 톡립성 깨짐: 테스트 케이스에서 설계한 독립적인 랜덤화가 깨질 수 있음
3. 디버깅 어려움: 랜덤값이 달라서 버그 재현이 힘들어짐
이를 해결하기 위해 sv에서는 객체와 스레드에 각기 다른 PRNG를 사용함

랜덤 안정성 - 계층적 시드주기
sv에서 모든 객체, 스레드는 고유시드와 자신만의 PRNG를 가짐
모든 객체, 스레드가 실행될 때 각 PRNG는 부모 PRNG로 부터 시드를 받아 구별된 많은 랜덤 스티뮬러스 스트림 생성 가능


테스트벤치 디버깅 시 랜덤 안정성이 있더라도 테스트벤치에서 추가, 삭제, 이동 등의 변화는 테스트벤치가 다른 랜덤 값을 생성하게 할 수 있음.
=> DUT 실패 디버깅 중이었다면 문제가 될 수 있음(테스트벤치는 더 이상 같은 스티뮬러스를 생성하지 않을 수 있기 때문) 이를 위해 새 객체, 스레드를 추가해 코드를 수정함으로써
