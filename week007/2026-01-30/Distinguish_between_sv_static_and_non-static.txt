static은 클래스의 것, non-static은 유일한 인스턴스의 것

static이 붙는 것들 - 클래스 레벨
1. 유일한 인스턴스를 관리하기 위한 것
클래스당 하나만 존재
객체가 없어도 접근 가능 :: 사용
싱글톤을 가리키는 포인터역할

2. 인스턴스를 얻기 위한 접근 함수
객체 없이 호출 가능해야 함
내부에서 m_inst를 생성 / 반환

static이어야 하는 이유
아직 객체가 없을 수도 있기 때문

static이 안 붙는 것들 - 인스턴스 레벨
실제 데이터 / 상태
int cfg_value;
string name;

싱글톤 객체가 가지고 있는 상태
개념적으로는 인스턴스의 속성
비록 인스턴스가 하나뿐이지만, 의미적으로는 객체의 데이터

실제 동작을 수행하는 메서드
function void set_cfg(int v);
function int get_cfg();
인스턴스 상태를 읽고/수정
다형성, 상속, override 가능

전부 static으로 만들면 안 되는 이유
상속 불가능 / 확장 어려움
지연 초기화 의미 없음
테스트별로 구현 교체 불가
객체라는 개념이 사라짐

싱글톤은:
static → 접근 경로 & 인스턴스 관리
non-static → 실제 기능과 상태
로 나눔
