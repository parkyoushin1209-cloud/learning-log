콜백
-콜백은 베이스 클래스가 확장될 것이라 가정해놓고 hook을 만들어 둔다.
-hook은 클래스의 확장을 가정 후 미리 확장 지점을 코드에 박아둔 것, 나중에 다른 코드가 끼어들 수 있도록 미리 만들어둔 공식적인 진입점이라고 볼 수 있음
-콜백 메서드는 모든 테스트 안에서 다르게 정의 가능함, 기존 클래스를 수정할 필요 없이 새 기능을 추가할 수 있다.
-콜백은 인터페이스 역할을 하므로 내부 구현은 가지지 않음
-객체를 직접 만들 필요가 없어 그 자체로 new가 필요하지 않고 확장된 클래스만 이용함
-콜백은 주로 에러 주입 또는 스코어보드에 데이터를 보내거나 functional coverage에 값을 모을 때 사용한다.
-콜백을 가진 트랜잭터가 예상대로 동작 안하면 디버그 콜벡을 추가해볼 수 있다. 트랜잭션을 display하기 위한 콜백 추가로 시작

virtual class Driver_cbs; // base callback class
  virtual task pre_tx(ref Transaction tr, ref bit drop);
    //기본적으로 여기서는 아무것도 가지지 않음
  endtask
  virtual task post_tx(ref Transaction tr);
    //기본적으로 여기서는 아무것도 가지지 않음
  endtask <callback 클래스 기본 틀>

추상 클래스의 타입의 변수 및 배열등은 선언할 수 있으며 배열의 경우 확장된 클래스들의 객체도 넣을 수 있다.
  class Driver_cbs_drop extends Driver_cbs;
    virtual task pre_tx(ref Transaction tr, ref bit drop)
      drop = (urandom_range(0,99) == 0); 1% 확률로 트랜잭션 드랍
    endtask
  endclass
