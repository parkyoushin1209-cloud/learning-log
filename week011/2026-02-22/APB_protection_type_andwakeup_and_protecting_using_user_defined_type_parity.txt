protection
설계가 복잡해지며 불법적인 트랜잭션으로부터 보호를 제공하는 것이 필요해짐
APB 인터페이스에서 이런 보로는 PPROT[2:0]으로 붜 제공됨
[0] = >  프로세싱 모드를 나타내기 위해 사용됨, pre가 더 높은 접근 수준을 가짐       LOW: normal       HIGH:preveileged
[1] = >  프로세싱 모드 사이에 더 높은 차별화가 요구되는 시스템에서 사용됨           LOW: secure        HIGH: non-secure
[2] = > 트랜잭션이 데이터인지 명령어인지 나타냄                                               LOW:data           HIGH: 명령어 접근

PPROT는 인터페이스에서 선택적 신호
com    req
 x         x    호환
 x         o    호환, completer는 접근 보호를 가지지 않으므로 PPROT가 무시될 수 있음
 o         x    비호환, 고정된 보호 속성이 기능적으로 옳다면 호환
 o         o    호환

RME는 arm 구조에 root and realm physical address space를 추가함 -> APB 트랜잭션 접근 권한 검사에 사용 가능
PNSE   1bit      requester      PSEL 활성화 시 반드시 유효해야 함
{PNSE, PPROT[1]} => secure, none_secure, root, realm임

RME_support 프로퍼티는 RME를 지원여부 표시에 사용 가능
TRUE :  지원함, 인터페이스에 PNSE 신호가 나타남
FALSE: 지원 안함 ifc에 PNSE 없음
PNSE가 있으면 PPROT도 있어야 함

RME_SUPPORT
req   com
F       F       호환
T       F       비호환
F       T       호환(PNSE 입력이  LOW로 묶임)
T       T      호환

pwakeup
동기화,  샘플링, 글리치 없는 상태, 활성화 타이밍, 컴플리터 대기, 클럭 게이팅,  트랜잭션 수용 

PCLK에 동기화되며 여러 클럭 도메인으로부터 비동기적으로 샘플링되기 위해 안정 상태를 유지해야 함
이를 위해 글리치 없는 상태가 필요하며 이는 레지스터 또는 글리치 프리 OR 트리로부터 바로 생성됨으로써 가능함
PSELx 어써션 전 중 후에 활성화 가능함
PREADY가 활성화 되기 전 PWAKEUP이 활성화되기까지 completer가 대기할 수 있으며, 신호는 존재하나 절대 활성화되지 않으면 인터페이스가 교착 상태에 빠질 수 있음
completer, requester측은 함께 클럭 게이팅돼는 것이 권장됨
따로 클럭 게이팅이 되는 경우 completer가 클록을 활성화하기 위해 PWAKEUP을 이용한다면 completer가 셋업 단계를 감지 못할 가능성이 있음
새 트랜잭션 수용 지연을 방지하기 위 PWAKEUP은 PSELx 어써션 보다  최소 한 사이클 전 활성화되도록 권장됨
클럭 제어기나 주변 장치로부터 라우팅할 수 있는 글리치 없는 신호를 제공하며 이를 통해 연결된 요소에 전원, 클럭 활성화할 수 있음

wakeip_signal property는 컴포넌트가 wakeup 신호를 지원하는지에 대한 여부를 나타낼 때 쓰임
True => Wakeup신호가 존재함
False => 존재하지 않음, wakeup_signal 속성이 정의돼지 않은 경우 False로 생각함

user signalinlg(데이터 폭, 신호 폭 크기, 사용의 문제점, 모든 사용자 신호를 포함할 수 있도록 대비
APB 프로토콜 인터페이스는 이런 신호들을 정의하고 있지 않음 => 두 컴포넌트가 비호환적인 방식으로 같은 신호 사용 시 상호운용성 문제 발생 가능
신호의 비트폭은 구현에 따라 달라질 수 있으며, 요청, 데이터, 반응에서 다를 수 있음
신호가 구현이 되더라도 completer가 이 신호들을 지원하도록 요구되지는 않음
데이터와 프로토콜 사이의 변환이 용이하도록 USER_DATA_WIDTH는 데이터 폭(바이트 단위)의 정수배로 할 것을 권장함
도메인 크로싱이나 인터커넥트에는 모든 사용자 신호를 포함할 수 있도록 대비하는 것이 좋으나 completer는 이를 반드시 포함해야할 의무가 없음
신호                   비트폭                   소스                       설명
PAUSER           USER_REQ_WIDTH     requester          사용자 정의 요청 속성 , PSELx가 활성화됐을 때 반드시 유효해야하며, 셋업, 액세스에서 같은 값을 가져야 함
PWUSER          USER_DATA_WIDTJ  requester          사용자 정의 쓰기 데이터 속성, PSELx, PWRITE가 활성화 됐을 때 반드시 유효해야하며, 셋업, 액세스에서 같은 값을 가져야 함
PRUSER           USER_DATA_WIDTH   completer         사용자 정의 읽기 데이터 속성, PSELx, PREADY, PENABLE이 어써트되고 PWRITE가 디어써트 됐을 때 유효해야 함
PBUSER           USER_RESP_WIDTH    completer         사용자 정의 반응 속성, PSELx, PREADY, PENABLE이 어써트 됐을 때 유효해야 함


IDLE(PSELx = 0) => SETUP(PSELX = 1, PENABLE=0) => ACCESS(PSELx = 1, PENABLE = 1, READY = 0 -> 1-이 때 다음 전송이 있다면 SETUP으로 없으면 IDLE로)

============================================================== check_type properety, 에러 확산, EDC, 종단간 보호 구현법, 에러 검출 어려운 경우
시스템 내 에러는 연결된 컴포넌트들로 퍼지고 수많은 에러를 유발할 수 있다.
Error Detection and Correct(EDC) 방식은 종단으로 동작해야 하며, src부터 dst까지 모든 로직, 와이어를 커버함
종단간 보호 구현 방법 => 컴포넌트에 커스터마이즈된 EDC 방식 사용 + 컴포넌트 사이에 간단한 에러 감지 방식 구현
컴포넌트 사이 로직은 없고 단일 비트 에러는 멀티 비트 에러로 확장 안됨
한 패리티 그룹 내 다수 비트 오류는 감지하기 어려우나 여러 그룹에 걸쳐 발생하면 검출 가능

인터페이스의 EDC 방식은 check_type property 로 정의됨
false: 인터페이스에 검사 신호가 없음
odd_parity_byte_all : 모든 신호들에 홀수 패리티 검사가 포함되며 각 패리티 신호의 비트는 8비트까지 커버
check_type이 선언되지 않았다면 false로 생각

바이트 패리티 인터페이스 보호를 위해 추가된 체크 신호에는 다음과 같은 공통 속성이 있음
1. 홀수 패리티 사용, 검사 신호는 각 인터페이스와 관련됨
2. 각 패리티 비트는 8비트까지만 커버, 이 제한은 각 패리티 비트를 생성하는데 사용할 수 있는 타이밍 여유 내에서 최대 3개의 로직레벨만 존재한다는 가정에 기반함(4단계 이상은 불가)
3. 중요 제어 신호를 커버하는 패리티 신호는 단일 패리티로 정의됨, 단일 홀수 패리티 비트는 원래의 중요한 제어 신호를 반전시킨 것임
[중요 제어 신호는 사용 가능한 타이밍 여유가 더 작을 가능성이 높음(= 시간 제약이 크므로 단일 비트 반전 방식을 사용함)]
4. 1비트보다 큰 검사 신호에 대해
검사 비트 n은 페이로드 비트 [(8n+7):(8n)] 에 상응, 페이로드 바이트가 정수 배가 아니면 페이로드의 Most significant portion에서 8비트보다 적은 비트를 커버
5. 검사 신호는 check enable이 참인 매 사이클에서 올바르게 구동돼야함
6. 패리티 신호는 연관된 페이로드의 모든 비트에 적절히 구동돼야 하며, 해당 비트가 전송에서 실제로 사용되는지 여부와는 무관
(ex. PWDATACHK의 모든 비트는 일부 바이트가 유효한 데이터 바이트가 아니어도 정확히 구동돼야 함)
7. 검사 신호가 커버하는 일부 신호가 인터페이스에 존재하지 않는 경우, 누락된 신호는 LOW로 간주됨
8. 검사 신호가 커버하는 신호가 인터페이스에 전혀 존재하지 않는 경우, 해당 검사 신호는 인터페이스에서 생략됨
