현대 사용되는 프레임워크는 UVM, VMM을 포함하며 클래스 기반임
어써션은 인터페이스를 통해 클래스 변수에 영향을 미칠 수 있음
일시적 어써션은 클래스 내에 사용 가능 동시 어써션은 불가능

어써션이 단순히 RTL의 반복이면 유용하지 않음(고수준 기능 요구사항 설명을 위해 의도된 것임)

SVA 사용 이점
1. standard 
SVA 의미론의 표준 정의는 다른 벤더들을 어써션에 대해 일관된 지원을 제공하는 데 가이드 해줌

2. documentation
간결한 표기법으로 이벤트 시퀀스, 일시적 속성, 요구사항 함축 묘사
모호하지 않게 프로토콜, ifc 가정을 포함한 설계의 특징을 문서화함
SV 데이터 구조, 태스크, 메서드, 큐, 연관 배열과 함께 쓰일 때 고수준 검증 구조 추상화 능력 제공
산업은 요구사항 속성, 어써션을 정의하기 위해 두가지 메서드 사용(임베디드, DUV에 묶인 외부 검증 프로그램 파일 메서드)

임베디드 메서드는 DUT에 묶이고 체커 또는 모듈 안에 어써션이 정의된 분리된 모델을 나타냄(디자인 모델링으로부터 속성 명세를 물리적으로 분리)
합성 가능한 RTL코드 터치 방지, 다른 검증 엔지니어가 디자인, ifc의 속성을 정의하는데 자주 사용됨
분리된 모델은 설계 속성 재확인을 돕고 검토 팀의 요구사항에 반하는 RTL설계 검토에 기반을 제공함
RTL 코드 수정, 타임 스탬프 추가 없이 어써션 모델 변경도 허용 => 재합성 필요 완화

3.whitebox verification through simulation
SVA와 제공된 설계 모듈은 고수준 계층에서 모듈 재사용, 혼합을 용이하게 함
시뮬레이션 또는 형식 검증동안 프로토콜, 이벤트 시퀀스가 맞지 않을 때를 빠르게 알아냄
모듈에 지역적이어서 관측성이 높고 모듈의 수명동안 유지(모듈이 수정되도) - 화이트 박스 어써션은 설계 구현이 업데이트돼도 유지돼야함
에러 소스에 가까운 모니터처럼 행동함

4. whitebox verifiacation through formal verification
설계 속성은 수학적으로 증명 가능, 속성에 반하는 반례를 자동적으로 생성 가능

5. blackbox verification
인터페이스 및 동작 요구사항을 사이클 타이밍 오차 범위 내에서 정의 가능(디자인 최적화를 위해)

6. assertion systhesis
어써션 합성은 RTL 디자인, TB를 취하고 설계 기능적 오퍼레이션에 대한 속성을 자동으로 합성
생성된 어써션은 설계 제약, 명세의 핵심을 잡게 해줌
그들의 블랙박스 체커가 코너케이스 버그 캐치, 검증 관측성 향상되게 보완해줌
다른 정보는 TB 홀에 노출된 기능적 커버리지 속성을 포함한 구현으로부터 추출될 수 있음

7. testbench support
SVA는 검증과정을 돕기 위해 현대 TB 접근과 함께 사용 가능함
SVA문은 DUV 결과 반응이 예상된 결과와 맞는지 결정하는데 작성될 수 있음
절차적 TB 코드 내 행동을 트리거하기 위해 SVA의 일시적 시퀀스 묘사 사용도 가능

8. access to verification libraries
SV를 사용해 검증 유닛의 라이브러리 정의/사용 가능
어써션 결과는 재활성 TB의 설계에 사용될 수 있음



어써션은 설계가 반드시 충족해야할 속성을 정의함(프로퍼티는 디자인에서 사용 가능한 변수로부터 표현될 수 있음
속성은 제어중심 설계 요구사항을 잡기에 유리한 반면 실제 셜계는 제어, 데이터 요소의 혼합을 포함함
추상 데이터 타입을 가지는 고수준 절차적 언서, 선언문 사이 상호작용때문에 형식언어는 설계의 데이터 측면 검증을 위해 필요해짐

어써션이 어디서 어떻게 사용되는가?
어써션은 requirement, application, interface, structural 로 분류 가능하며 다양한 추상화 수준 커버 가능
동시 어써션은 ifc, module, checker, program에는 가능하나 class에는 불가능, 하지만 클래스 변수는 ifc로 복사될 수 있고 ifc내에서 어써션 사용 가능

1. 설계의도 파악 뿐만 아니라 data_abort 같은 신호의 필요성도 명시 가능
2. 프로토콜 정의 및 검증 가능하게 할 수 있음 , 신호의 값과 여러 시간동안 신호 사이의 관계를 정의하는 어써션을 통해
3. IP블록에 포함된 어써션의 경우 상위 시스템으로 IP가 통합될 때 적절히 통합될수 있도록 보장함
4. 기능적 커버리지 메트릭스를 용이하게 함
커버리지 카테고리는 
어써션 커버리지: 시나리오, 이벤트의 시퀀스를 다룸
데이터 커버리지 : 변수의 값의 커버리지를 다룸 + 크로스 커버리지    로 나뉜다

시뮬레이션 벤더는 어써션에서 수치 수집을 제공해 시뮬레이션 피드백 산출을 돕는다
형식 툴은 증명 검색의 범위, 도달 불가 같은 정보를 갖춘다.
다른 툴은 전체 설계의 어써션 모니터링 기반 수치를 제공한다.
5. 프로퍼티의 위반을 입증하기 위한 반례 생성
형식 검증 툴은 제약(assume, restrict)과 함께 어써션을 사용한다. 설계가 요구사항을 충족하는지 결정하기 위해
충족하지 않으면 규칙 위반이 발생한 조건을 설명하기 위한 반례를 생성한다 => 설계의 검증이 용이해짐
