스레드 : 프로퍼티의 선행 클럭킹 이벤트에서 시작하는 평가 시도의 성공에 대한 검색 경로
시퀀스는 싱글 스레드, 멀티 스레드로 분리 가능

싱글 스레드 and singly matced sequence
single matched 검색 경로를 가짐
시퀀스가 다음의 연산자를 포함하지 않을 때 존재 가능
and, intersect, or, delay range, 연속 범위 반복, 불연속 반복 //goto 연산자는 멀티스레드지만 단 하나의 매치만 가질 수 있음

멀티 스레드 시퀀스
시퀀스가 다음의 것 중 하나라도 가지면 멀티 스레드임
and, intersect, or, 지연 범위, 연속 범위 반복, 불연속 반복

스레드, 시퀀스에서 중요한 개념    ||================결과, 시퀀스 평가의 차이점, 멀티 스레드 매치===================||
- 스레드 평가 후 결과는 matched, non-matched
스레드는 어써션이 아님 -> pass/success/fail로 평가하는건 부정확
매치는 참 값을 가짐

- 프로퍼티의 평가와 달리 시퀀스의 평가에는 공허가 없음(시퀀스뿐인 프로퍼티는 항상 공허하지 않음)
함축 연산자로 구분도 가능

-멀티 스레드를 가지는 스레드는 여러 매치를 가질 수도 있음(쓰레드당 1개씩)
멀티스레드 시퀀스가 선행조건으로 쓰이면 어써션이 성공적으로 끝나기 위해 후속조건이 반드시 테스트 돼야함

-멀티 스레드 시퀀스는 첫 매치에서 종료될 수도 있음
암묵적 first match는 시퀀스가 프로퍼티로서 사용될 때나 시퀀스가 프로퍼티의 후속조건으로 쓰일 때 존재

-명시적 first match() 함수도 매치에서 멀티 스레드 시퀀스를 끝낼 수 있음
암묵적 first_match가 그 측면을 커버할 때 (with cover문) first_match 함수 불필요
보편적으로 멀티 스레드 시퀀스가 선행조건일 때 필요함


어써션에서 멀티스레드 시퀀스의 영향
시퀀스가 프로퍼티의 선행조건보다는 후속조건으로 사용된다면 멀티 스레드 시퀀스를 가진 어써션은 다르게 진행될 수 있음
선행조건에 멀티 스레드 시퀀스가 존재한다면 각 스레드는 결과를 결정하기 위해 평가됨(vacuous, pass, fail)

규칙
멀티 스레드 시퀀스로 시작한 어써션은 결과를 위해 다음의 기준을 가짐
-어써션이 실패하지 않는 한, 매칭되는 선행, 후속 조건 쌍을 찾기 위해 모든 스레드가 탐색돼야함
실패하면 검색은 멈추며, 선행조건이 매치되고 후속 조건이 패하면 실패

-성공을 위해서는 두 요구조건이 충족돼야함
검색에서 실패가 있으면 안됨
선행/후속 조건의 모든 스레드가 성공해야 함(성공에는 두가지 타입이 있음)
a. 공허한 성공: 1. 선행조건의 모든 스레드가 매치하지 않으면 공허한 성공
                     2.  공허는 매치된 선행조건을 가지나 후속 조건이 공허할 때도 발생 가능
b. 패스/공허하지 않음: 공허하지 않은 패스(또는 성공)를 위해 최소한 1개의 공허하지 않은 성공을 가지는 선행조건이 있어야 함
또한 후속조건에서 실패가 없어야 함, 몇몇 스레드는 공허할 수도 있음

apAB: assert property(a[*1:2] ##1 b |-> c);
각 선행 clk event에서 선행조건 평가 시도가 있음
a가 0이면 공허한 성공(모든 스레드도 공허할 것임)
a가 1이면 두개의 스레드가 시작되고 더 평가됨

어써션은 fail/pass/success/fail vacuously / be disabled일 것임
툴은 공허/공허x 실패를 모두 실패로 여기며 구분 안 함

가이드라인
선행조건으로 쓰이는 시퀀스 정의 시, 예상치 못한 결과 방지를 위해 트리거 조건이 유일하게 보장
시퀀스가 멀티 스레드를 가진다면 fisrt match 연산자 사용
first match 없이 무한 범위의 선행조건을 가지는 프로퍼티의 어써션은 절대 성공 못함(성공을 위해서는 가능한 모든 조합이 테스트 돼야 하므로 실패는 가능)
first match()는 효율성 측면에서 좋지 않음
goto 연산자와 intersect 연산자를 함께 써서 대체(선행조건이 하나의 매치만을 가지게 함)
ap_1thread_success : assert property(@(posedge clk) $rose(a) ##2 b[->1] ##1 [*0:$] intersect 1[*6] |=> c);

후속 조건에서 멀티 스레드 시퀀스
규칙: 후속조건으로 쓰이는 멀티 스레드 시퀀스를 가지는 프로퍼티의 어써션의 경우 어떤 후속조건의 매치도 매칭되는 선행조건의 스레드를 끝낸다
선행조건 매치 + 가능한 후속 조건이 모두 실행됐으나 매치 없음 -> 실패

후속조건에서 강한/약한 시퀀스
후속조건이 약한 시퀀스라면 시뮬레이션이 끝날 때 남아있는 시퀀스는 참으로 간주하며, 기본값임
강한 시퀀스라면 거짓으로 간주
안 끝나는 경우 strong 사용하는게 좋음
assert property (@(posedge clk) a |-> strong([1:$]b));  //ok
assert property (@(posedge clk) a |-> ([1:$]b)); // not good

questa에서 vsim은 -onfinish라는 스위치를 가지며 모드로 ask, stop, exit, final을 가질 수 있음
ask: 사용자에세 대화창이나 프롬프트로 종료 여부 물어봄
stop: 시뮬 중단 후 디버깅을 위해 상호작용 모드로 남겨줌
exit :  묻지 않고 종료
final: 시퀀스의 마지막 상태 정리 후 종료

선제/후속조건에서의 멀티 스레드 시퀀스
규칙: 프로퍼티의 어써션이 선행조건으로 쓰인 멀티 스레드 시퀀스를 가진다면 모든 스레드는 후속조건의 첫 매치와 일치하는 선행조건을 찾기 위해 실행돼야 함(실패가 아닌 이상)
매치된 전제와 상응하는 후속 레드가 없음 실패

어써션 성공 조건
매치된 전제와 매치되는 후속 찾는 중 실패가 없어야 함
전제/후속의 모든 스레드가 성공해야 함(공허또는 true pass)

여러 (선행조건/후속조건) 짝이 있는 경우
first match로 선행조건 묶기
(first match($rose(a) ##1 b[*1:3]) |-> first match(##[1:3] c) |-> ##[1:4] d);
(first match($rose(a) ##1 b[*1:3]) |-> ##[1:3] c |-> ##[1:4] d);

연속적 반복
가이드라인: 선행조건인 시퀀스에 first match 연산자 사용하고 범위 반복 범위 연산자 사용
a[*1:2]##1 b |-> c 대신
firsy match(a[*1:2] ##1 b) |-> c 사용

[*n] 정확히 n번 반복, 시퀀스 표현식은 단일 항 표현의 시퀀스(a)가 될 수 있음
[*n:m] , [+], [*]
명시된 범위 안에서 반복 돼야 함
반복 구성을 따르는 연결된 시퀀스가 있을 때 그 시퀀스도 암묵적으로 반복
개개의 스레드를 or처리한 시퀀스와 등가
(a |-> (b[*1:3] ##1 c))
= (a |-> ((b[*1] or b[*2] or b[*3]) ##1 c))
= (a |-> (b[*1] ##1 c) or (b[*2] ##1 c) or (b[*3] ##1 c));

핵심 정리
선행조건이 멀티 스레드 시퀀스다 => first match로 묶자
하나라도 실패하면 실패다 <=> 성공을 위해서는 전부 성공해야 한다(공허든 true든)
후속 조건이 끝나지 않는다면 strong 사용하자, goto, intersect 연산자 함께 사용으로 대체 가능
