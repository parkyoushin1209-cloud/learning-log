c++ 자원과 예외(1)
프로그램 기본적 원칙: 취득한 자원을 어떤 방법으로든 그 자원을 관리하는 한 부분에 반환해야 함
(자원은 취득 후 반드시 반환(해제)하거나 자원관리자가 회수해야 하는 무언가임)

vector를 비롯해 자원해제를 수반하는 객체를 사용할 때는 자원의 소유자나 핸들이 자원해제를 책임져야 한다.

자원관리의 잠재적인 문제점
1. 자유 저장 영역 할당 후 다른 거 가리키게 하면 포인팅 대상을 변경해도 알 수 없음 
2. delete 실행 전 return 으로 종료되면 절대 실행 안됨
3. 예외를 던져서 delete이 절대 실행되지 않을 수 있음
=> try...catch 사용 가능하나 유지 보수 어려움, 오류 가능성 올라감, 가독성 떨어짐

자원취득은 곧 초기화(Resource acquisition is initialization- RAII)
객체의 생성자에서 자원 취득, 소멸자에서 자원 해제

vector<int>* make_vec() {
	vector<int>* p = new vector<int>;
	try {
		//.. 벡터에 데이터 채움 이 과정에서 예외 발생 가능
		return p;
	}
	catch (...) {
		delete p; // 지역적으로 자원 해제 후
		throw; // 예외를 다시 던져 호출자에게 예외를 알림
	}
} // 이 또한 코드가 보기 안 좋음

//RAII사용, 즉 (vector<int>를 포함하는 객체를 만들어 예외 발생 시 vector 삭제) => <memory>의 unique_ptr이용
vector<int>* make_vec() {
	unique_ptr<vector<int>>p{ new vector<int> };
	//.. 벡터에 데이터 채움 이 과정에서 예외 발생 가능
	return p.release();
}
/*unique_ptr
포인터를 저장하는 객체, ->, * 사용 가능
파괴될 때 소유한(가리키는)객체를 delete 함
p.release() p로부터 소유하고 있는 포인터를 추출해 반환 가능하며 p가 nullptr을 가리키게 하므로 문제 없음
return p; 사용시 함수가 반환하는 포인터를 delete할 필요도 없음
unique_ptr이 다른 unique_ptr을 가리키게 할 수 없다는 제약이 존재하나 보통의 포인터에 비해 추가적인 비용이 없음

객체 삭제, 복사를 모두 처리 가능한 포인터를 원하면 shared_ptr이용
=> 마지막으로 파괴되는 복사본이 가리키는 객체를 파괴하기 위해 참조 카운트를 이용해 비용은 더 큼
*/
