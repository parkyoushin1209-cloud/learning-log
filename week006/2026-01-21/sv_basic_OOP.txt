
-OOP 용어
class: 변수, 루틴 등을 포함하는 기본 구성 단위
object: class의 인스턴스
handle: 객체를 가리키는 포인터
property: 값을 저장하는 변수
method: 태스크와 함수에 포함된 변수를 조작하는 절차적 코드(클래스의 루틴)
prototype: 클래스 루틴의 헤더(반환형, 인자목록, 타입, 이름을 보여줌)

-클래스의 정의 위치
모듈, 프로그램, 패키지 안이나 밖 모두 가능
파일 수가 많아지면 관련된 클래스, 타입 정의를 패키지에 두면 좋음

-새 객체 생성
베릴로그의 모듈은 컴파일 때 instantiated, 클래스는 시뮬레이션 때 테스트벤치에서 사용하면, 사용되기 전 instantiated 돼야함
Transaction tr; Transaction 클래스 타입의 핸들 tr 생성
tr = new(); 트랜잭션 객체 할당, new()는 생성자

생성자는 원하는 값으로 세팅하기 위해 따로 정의 가능함 (코드 참조)
생성자는 특별한 함수이며 자동으로 클래스와 같은 타입의 핸들은 반환함

선언부와 생성자는 구분해야 함 Transaction tr = new()의 형식으로 쓰지 않기 합법적이고 장황하지 않으나 객체 생성, 초기화가 즉시 발생돼 초기값 설정, 조건부 초기화, 설정 주입 등을 삽입할 기회가 없음

new(), new[]의 차이점: new()는 단일 객체 생성 시 사용하며 객체 값을 설정하기 위한 인자를 가질 수 있다. new[]는 여러 요소를 가진 배열을 생성하며 배열 요소 수를 나타내기 위한 단일 값을 가진다.

핸들 선언과 객체 생성은 서로 다른 것이며 핸들은 시뮬레이션동안 많은 객체를 가리킬 수 있으나 한 시점에 하나씩만 가리킨다.

-객체 할당 해제
기본적으로 객체는 가리키는 핸들이 없을 시 자동으로 할당해제 된다. 핸들에 새 객체를 덮어씌우면 이전 객체는 가리키지 않게 되고 null을 대입 시 아무 객체도 가리키지 않게된다.
핸들은 같은 타입의 객체만 참조 가능하며 수정 불가능하다. 또한 핸들은 항상 유효하다
객체가 분기된 쓰레드를 가지는 루틴 포함시 완전히 실행되어야 해제 가능하다.

-객체 사용 
객체명.클래스변수/루틴 명으로 사용 가능함
strict OOP에서 객체 내 변수 접근은 이후에도 내부 구현 변경 능력을 유지하기 위해 get(), put()등 접근 함수를 통해서만 가능하다.
테스트벤치의 목적은 최대한 많은 경우를 시험해보는 것이며 이를 위해 constrained random stimulus 생성이 중요하고 이는 변수가 메서드를 통한 접근 뒤헤 숨어있으면 수행 불가능하다 따라서 어디서나 접근 가능한 public 변수 사용

-클래스 메서드
클래스 메서드는 기본적으로 automatic 저장 공간을 사용한다. 
여러 클래스의 동일한 이름의 함수가 존재해도 문제 없으며 이는 핸들로 타입에 기반해 올바르게 표현 가능하기 때문이다.

-클래스 외부에 메서드 정의
코드는 한 화면에서 전부 볼 수 있는게 이해하기 쉽다. 이를 위해 클래스 메서드를 외부로 옮길 수 있으며 이는 클래스에는 extern prototype, 외부에 원래 메서드를 그대로 옮기고 메서드 이름 앞에 클래스명:: 만 추가하면된다.
이 때 프로토타입과 몸체의 매치를 정확히하기, 클래스 내부 프로토타입은 local, protected, virtual 등의 수식어구를 가질 수 있으며 외부에서는 불가능/ 인자가 기본 값을 가지면 프로토타입 안에 반드시 주어져야 하며 본첸에서는 선택적이다.

-정적 변수
간단한 정적 변수=> 클래스 내부에 static을 사용해 정의하며 이 변수는 모든 클래스 객체가 공유할 수 있게 된다.
ID 필드는 객체 추적에 좋으며 테스트 벤치에서 디버깅 시 종종 고유값이 필요할 수 있는데 이 때도 사용 가능하다
전역 변수 생성 시 클래스 레벨 static 변수 사용 고려하기.

-static 변수는 클래스명::정적변수명 으로도 접근 가능

-static 변수 초기화
보통 선언부에서 초기화되며, 반드시 첫 객체 생성 전 초기화되어야 한다.
static 변수는 클래스의 모든 인스턴스가 하나의 객체로부터 정보를 필요로 할 때 사용 가능하다.

-static method
객체 생성 전이라도 클래스 내부에 정적 변수를 읽고 쓸 수 있는 정적 메서드를 생성할 수 있다.
정적 변수로 non-static 변수를 읽고 쓰는 것은 금지된다.

-범위 규칙
테스트벤치 작성 시 많은 변수를 생성, 참조할 필요가 있으며 시스템 베릴로그는 기본적으로 다음의 규칙을 따른다.
1. scope는 코드의 블록을 의미(module, program, task, function, class, begin/end block등) for, foreach 루프는 자동으로 블록을 생성한다.(인덱스 변수를 루프의 스코프 범위 내에서 local로 선언/생성 가능)
2. 새 변수는 블록에서만 정의 가능하며 sv에서는 명명되지 않은 begin end 블록에서도 가능하다 이 경우 툴에 따라 계층적 이름이 다를 수 있다.
3. 이름은 현재 범위나 절대적 시작점($root)를 기준으로 둘 수 있으며 상대적 이름일 경우 찾을 때까지 범위를 조금씩 넓혀가며 $root를 사용한다면 명확히 할 수 있다.
테스트벤치에서
변수는 initial 블록 내에서만 사용하면 이 블록안에 두고 프로그램에서도 선언 가능하다.
+클래스들은 모듈, 프로그램 밖 패키지 내부에 선언해 모든 테스트벤치에서 공유 가능하게 하라
+일시적 변수는 가능한 좁은 영역에 두어라
+블록 안에 선언되지 않은 변수를 사용했는데(for문의 인덱스 변수 등) 프로그램 블록 안에 같은 이름의 변수가 존재한다면 클래스는 그 변수를 가져다 쓴다. (프로그램 -> 클래스 -> 함수 -> for문 일 때)
=> 이를 피하기 위해 클래스를 패키지로 옮겨서 클래스가 프로그램 레벤 변수를 사용 못하게 할 수 있다.

this
클래스 내부 깊은 곳에서 명확히 클래스 레벨 객체 참조시 this 키워드로 모호함을 제거할 수 있다.(보통 클래스 변수/인자랑 같은 이름을 사용하는 생성자 안에서 사용함) - (코드 참조)
