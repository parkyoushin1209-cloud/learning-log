인터페이스 = 여러 개의 와이어(신호)를 묶어 놓은 systemverilog의 구성 요소
->타이밍, 신호 방향, 기능적 코드 등을 가질 수 있으며 모듈처럼 파생되거나 신호처럼 포트로 연결된다.

TB-DUT통신
1. 포트를 통한 통신 -> 핀 수 많아지면 여러 페이지의 신호 포트 선언 -> 에러 발생하기 쉬움, 신호는 다양한 계층의 층을 지나므로 신호 추가가 매우 까다로움
2. 인터페이스 구조 -> 연결 간략화를 도움 + 인터페이스 신호는 논블로킹으로 할당해야 함, 모듈/프로그램 외부에 선언하며 헤더로 사용할 경우 가려질 수 있음
인터 페이스 연결은 다른 코드 참고
인터페이스내 modport를 통해 신호 그룹, 방향을 명시할 수 있음/ modport에는 각 모듈별 사용하는 신호만 리스트로 들어가도 됨

인터페이스 트레이드-오프
장점
1. 디자인에 재사용하기에 이상적이다.(두 블록이 두 개이상의 명시된 프로토콜로 통신/ 신호 그룹을 자주 이용할 경우 추가적으로 가상의 인테페이스 사용하기)
2. 여러곳에서 사용하는 신호를 취해 중심적 공간에 두어 신호를 잘 못 연결할 가능성을 줄여줌
3. 신호 추가시 모듈이 아닌 인터페이스에 한 번만 선언하면 된다(에러 줄여줌)
4. 모드포트는 모듈이 신호의 부분집합에 더 쉽게 접근하게 해주며 추가 확인을 위해 방향 명시도 가능하게 해준다.
단점
1. 신호 리스트를 가진 포트를 사용해 모드포트를 가진 인터페이스가 장황해진다.
2. 신호 + 인터페이스 이름을 모두 사용하므로 모듈이 더 장황해질 수 있으나 디버깅에는 더 좋다.
3. 단일 프로토콜로 두 블록 연결시 재사용 안 하면 포트로 연결보다 더 수고스러울 수 있다.
4. 서로 다른 두 개의 인터페이스를 연결하기 어렵다. 새로운 인터페이스는 새로운 신호도 추가적으로 가질 수 있어 각각의 신호를 분리하고 적절히 구동해야 할 수도 있다.
사용예시는 sutherland(2006) 참고

인터페이스에서 VMM은 wire 사용을 원칙으로 함
절차적 할당문을 가진 인터페이스의 비동기 신호를 위해서는 logic 사용
wire는 계속적 할당만 가능
동기식 신호는 둘 다 가능
logic 사용 이점 1. 의도치 않게 multiple structural driver이용시 에러가 발생함 => 재사용시 많으면 logic을 wire로 클럭킹 블록을 거치지 않을 경우 절차적 할당문을 수정하기만 하면 됨
wire는 assign문도 같이 써줘야 해서 logic을 쓰면 더 간결해짐
