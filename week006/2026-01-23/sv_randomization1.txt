디자인 복잡성 증가로 CRT가 중요해짐.
CRT는 reference model, transfer function, 다른 기술을 이요한 결과 예측 환경과 스티뮬러스의 효율성 측정을 위한 functional coverage를 요구
구성 부분으로는 DUT입력을 생성을 위해 랜덤 값의 스트림을 이용하는 테스트 코드, 의사난수생성기에 주는 시드가 있음

랜덤화할거
데이터필드의 경우 $random만 호출하면 되 생성하기 쉬우나 버그 발견 측면에서 효율성이 낮다.
찾기 힘든 버그는 조작 로직에 있어서 컨트롤 패스 분기점에서의 선택을 랜덤화할 필요가 있다.
1. device configuration
CRT방법을 이용해 단일 채널을 위한 파라미터를 랜덤화하는 테스트벤치를 작성하고 전체 디바이스 설정을 위해 루프에 둔다.
2. environment configuration
디바이스는 다른 디바이스를 포함한 환경에서 작동한다
=> 객체의 수, 객체를 설정하는 방법을 포함한 전체 환경을 랜덤화해야 한다.
3. primary input data
  트랜잭션에 랜덤 값을 채움, 트랜잭션 클래스를 세싦하게 준비한다면 쉬울 것이다.
4. encapsulated input data
  많은 디바이스는 스티뮬러스의 여러 층을 처리할 것이다. 이 층은 각각의 컨트롤 필드를 가지고 각 필드마다 새로운 조합을 찾기 위해 런덤화가 가능
  => 데이터와 둘러싼 층을 랜덤화, 유효한 컨트롤 필드를 생성하고 에러 주입도 허용하는 제약 작성이 필요하다.
5. protocol exceeptions, errors and violation
  잘못될 수 있는 케이스를 예상하고 시스템에 주입, 디자인이 유효하지 않은 상태로 가거나 잠기는 것 없이 처리 가능해야 함
  기능 명세의 끝자락이나 살짝 넘어서 테스트
6. delay
  bus grant는 request를 받은 후 1~3사이클 후에 오며 메모리로부터의 데이터는 4~10 버스 사이클 때 유효하다.
  데스트벤치는 모든 테스트 동안 랜덤하고 합법적인 지연을 이용해 디자인 버그에 노출된 조합을 찾는 것을 목표로 한다.
  사이클레벨 이하에서 몇몇 디자인은 클럭 지터에 민감 => 클럭 에지를 앞뒤로 조금씩 옮겨봄으로써 클럭 사이클의 작은 변화에 어떻게 반응하는지 확인
  클럭 발생기는 테스트벤치 밖 모듈에 두어 다른 디자인 이벤트, 액티브 지역 인벤트 생성 가능
  주파수 등의 파라미터를 가져야 하며 설정 단계에서 테스트 벤치에 의해 조정될 수 있는 오프셋을 가져야 함

시스템 베릴로그에서 랜덤화를 위해서는 관련된 랜덤 변수를 그룹으로 클래스에 저장하고 랜덤 solver에 랜덤 값을 채워야 한다.

  rand: 클래스를 랜덤화하는 모든 시간에 변수에 값 할당됨 다음 값으로는 새 값 또는 현재 값이 가능
  randc: 모든 가능한 값이 한 번씩 할당되기 전까지 같은 값을 반복하지 않는다.
  constraint는 변수가 반드시 가져야하는 표현의 부분으로 선언적이기에 }를 사용한다.
  randomize() 함수는 제약이 있을 때 제약을 어기는 경우 발견 시 0을 반환한다. 또한 클래스 내 rand, randc 변수에 랜덤 값 할당, 모든 활성화된 제약이 준수됨을 보장한다.

  constraint solver는 제약을 만족하는 값을 선택한다(값은 초기 시드로부터 시작되는 의사 난수 생성기에서 온다.)
  시뮬레이터에 같은 시드, 테스트벤치를 주면 같은 결과를 보이며 툴버전 디버그 레벨 등의 스위치 변화는 다른 결과를 초래할 수 있다.

  랜덤화 가능한 것으로는
  전체적인 변수 랜덤화를 허용(2,4 상태, 비트의 간단한 집합 포함) 랜덤 문자열,핸들 참조등은 안 된다. real 변수의 경우 LRM상 아직 규정 안됨

  constraint 블록 
  여러 표현을 두기 위해 }를 사용하며 
  한 개의 표현식 안에는 한 개의 연산자만 가능하다 
  할당문은 사용할 수 없으며 값을 지정하기 위해서는 ==을 사용 가능하다. (하나 이상의 랜덤 변수들 간의 복잡한 관계도 형성 가능하다)
  이 블록 안 변수는 rand나 randc 여야 하며 논랜덤 변수에 대해서는 assert, if문을 사용해라
  가중치를 적용함으로써 스티뮬러스를 특정 방향으로 치우치게 할 수 있으며 :=는 모두 같은 값을 부여 :/는 변수들끼리 동등하게 나눠갖는다
    
  dist연산자
  -가중치 분포 생성 가능  -값과 가중치 리스트를 가짐  -:=, :/ 로 분리  -두 값은 상수나 변수 가능
    -단일  값이나 [lo:hi]등의 범위가 될 수 있다.  -가중치는 백분율을 나타내며 합이 100이 될 필요는 없다.

    inside 연산자로 값의 집합 생성 가능 c inside {[lo:hi]} -> 모든 값의 확률은 다른 제약이 없는한 동일하다.
    inside를 이용해 벡터도 집합으로 넣을 수 있다.

    집합에서 동적으로 추가, 제어를 원할 경우 inside로 선택 후 천천 히 줄일 수 있으나 이는 solver가 많은 제약을 풀 게 될 수 있어 비용이 크다
    짧고 일정한 시간이 드는 randc 변수로 인덱스를 만들어 배열 요소 수만큼 반복하면 같은 효과를 얻을 수 있다.

    양뱡향 제약: 모든 제약은 병렬적으로 풀리며 표현식들 사이에 서로 영향을 줄 수도 있다.

    함의 제약 x->y 형태 = (!x||y)와 동일하다.
    등가 연산자 <->로 나타낼 수 있으며 logical xnor과 기능이 같다.
    solution probabilities
    sv는 특정한 해를 찾아줄지는 않으나 가중치를 이요해 치우치게 할 수는 있다.
    제약이 없을 경우 모든 가능한 경우에서의 확률은 동일하다
    함의가 있을 경우 (x==0) -> (y==0)이고 x는 0,1 가능 y는 0,1,2,3 가능할 경우 x=0일 때의 확률은 y가 0일 때 1/2이고 나머지는 0이다.
    solve x before y를 사용할 경우 x의 모든 값에 대해 확률을 동일하게 부여하고 y를 통해 확률을 더 나눈다.
