타입 선택 고려 요소
a = fixed_array, b = dynamic_array, c = queue, d = associative array
1. 유동성
a : 연속된 양수 접근, 컴파일 때 사이즈 알 경우
b:  연속된 양수 접근, 런타임때까지 사이즈 모름, 배열 조작 루틴으로 조작 가능
c: 루틴 적용 사능. 도중에 사이즈 변화 많을 시 사용(scoreboard)
d: 사이즈 관계 없이, 널리 퍼져있는 값, cmd(값으로 조회)

2. 메모리 사용
2상태는 메모리 사용량 적음, 3비트 배수 크기 데이터 사용, packed array로 메모리 공간 절약, 1000개 이하 상관 없음
a, b: 1000~100만개 active elements, 데이터 set 개수 변화시 new[] 사용
c: queue는 추가적 포인터 사용 -> 효율성 떨어짐
d: megabyte이상 

3. 속도
a,b: 모든 요소 접근 송도 동일(배열 크기 상관 없이)
c: 접근 시간 비슷, push,pop 가능, 중간에 삽입 시 shift 많아져 테스트벤치 속도 떨어짐
d: 요소 접근법 규정은 안되 있음, 보통 해쉬테이블, 트리 이용, 많은 계산을 요구해 속도 떨어짐

4.데이터 접근(정렬은 전부 가능, 얼마나 자주 값을 추가할지)
a,b : 모든 요소 한 번에 받을 때 사용(할당 1회)
c: 값이 여러번 천천히 들어올 때 사용
d: unique, 불연속적 값 , 인덱스 이용으로 접근 속도 빨라짐, first, next, prev 사용 가능, 쓰여진 값은 exist로 확인, 요소 사용 끝나면 delete로 지움

5. 최선의 데이터 구조 선택
1.network packet(속성: 고정 사이즈, 연소적 접근): a,b 이용
2. scoreboard of expected values(속성: 값에 의한 접근, 런타임까지 사이즈 모름, 사이즈 변화가 지속적임): 트랙잰션에 고정 ip 제공 가능 => index로 랜덤 => unique value찾기 가능
100개 이상 요소, 중간값 삽입 삭제 많으면 d가 효율적일 수 있음
3.sorted structure: queue(예측된 순서면) 아니면 d
4. 100만개 이상 매우 큰 메모리 모델링 d, 2상태 packed로 시뮬레이션 메모리 줄이기
