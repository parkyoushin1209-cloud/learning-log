1. static 저장공간 사용이 위험한 이유는 무엇인가?
static 저장공간의 경우 그 함수를 동시 호출하게 될 경우 그 저장공간을 여러 스레드가 공유하게 될수도 있다는 점이다. 즉 나중에 호출된 함수가 이전에 호출된 함수의 결과를 덮어써버릴 수 있으며
sv의 컴파일러가 문자열의 복사본을 생성하지 않는 한 해결할 수 없으며 sv의 스케줄러는 c++ 코드에 절대적으로 개입 불가능하다. 이를 해결하기 위한 방안으로 호출자가 버퍼를 넘겨주는 방법, 동적
할당을 이용하는 방법 Mutex/Lock 사용, sv에서 스트링 처리 하는 방법, Thread local storage(TLS) 사용 등이 있다.

1-1 호출자가 버퍼를 넘겨주는 방식
void print_rgb(p_rgb rgb, char *out) {
    sprintf(out, "%02x,%02x,%02x", rgb->r, rgb->g, rgb->b);
}
1-2 TLS사용 방식
thread_local static char s[32]; (c++11)

1-3 동적할당 이용
char* print_rgb(p_rgb rgb) {
    char* s = (char*)malloc(32);
    sprintf(s, "%02x,%02x,%02x", rgb->r, rgb->g, rgb->b);
    return s;
}
1-4 뮤텍스/락 사용
static char s[32];
static std::mutex m;

char* print_rgb(p_rgb rgb) {
    std::lock_guard<std::mutex> lock(m);
    sprintf(s, "%02x,%02x,%02x", rgb->r, rgb->g, rgb->b);
    return s;
}

1-5 sv에서 스트링 처리
int get_rgb(p_rgb rgb) {
    return (rgb->r << 16) | (rgb->g << 8) | rgb->b;
}

int v = get_rgb(pstruct);
string s = $sformatf("%02x,%02x,%02x",
                     v[23:16], v[15:8], v[7:0]);

2. 구조체에서 .을 사용하는 경우와 ->를 사용하는 경우의 차이점은 무엇인가?
구조체 그 자체를 사용할 경우는 .을 사용하며 구초체를 가리키는 포인터를 사용할 경우에는 ->를 사용한다. 적절히 사용하지 않는다면 컴파일 에러가 발생할 수 있다.
