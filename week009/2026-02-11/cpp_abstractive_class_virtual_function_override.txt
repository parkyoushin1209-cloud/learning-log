-복사와 변경 가능성
계층 구조를 이루는 클래스와 참조에 의한 전달을 함께 사용할 경우 기본 복사는 안 어울림(Shape는 Circle의 반지름에 대한 정보를 갖고 있지 않는 등)
기본 복사 방지하기(push_back의 경우도 기본 복사를 사용하므로 막으면 복사 못함)
Shape(const Shape&)=delete;
Shape operator=(const Shape&)=delete  처럼 =delete사용 
이후 복사를 수행하길 원하면 clone()과 같이 명시적 함수를 만들기(멤버를 읽는 함수들이 사본을 만드는데 충분한 경우만 가능함)

-기반 클래스와 파생 클래스
파생: 한 클래스를 다른 클래스에 기반을 두어 정의하는 방법(원래 클래스 대신 사용 가능)
=>모든 멤버를 물려 받는 상속이 가능하며 자신만의 멤버도 추가 가능함

가상함수: 기반 클래스에 정의된 함수와 이름과 타입이 동일한 함수를 파생클래스에 정의한 후 사용자가 기반 클래스의 해당 함수를 호출할 때 실제로는 파생 클래스의 함수를 호출하는 방법(실행 시간 다형성, 동적 디스패치, 실행시간 디스패치)

private, protected 멤버: 클래스 구혀느이 상세 내용을 비공개로 만들어 유지 보수를 어렵게 하는 외부로부터의 직접적 사용 방지(캡슐화)

상속, 실행시간 다형성, 캡슐화는 가장 일반적인 OOP를 정의하는 특성임

-객체 레이아웃
클래스의 멤버가 객체의 레이아웃을 결정하며 이 데이터 멤버는 메모리에 순서대로 적재됨
가상 함수를 처리하려면 super의 어떤 함수가 호출되었는지를 알기 위해 추가적인 정보가 필요함 => 보통 함수의 목록의 주소를 객체에 추가(함수의 목록을 가상 함수테이블이라 하며 클래스당 하나씩 가짐, 목록의 주소를 가상 포인터라 함)
vptr이 가리키는 적절한 ptbl에서 알맞은 함수 호출(참조 2번 함수 호출 1번의 소모 비용)

-파생 클래스와 가상 함수 정의
struct Circle : Shape{/*..*/}; 형태로 정의할 수 있으며 struct의 멤버는 public이므로 다음의 표현과 동일함 => class Circle : public Shape{public/*...*/};
클래스 선언 내부 가상 함수에는 virtual 사용 외부에서는 사용 안함

-오버라이딩
가상 함수를 오버라이드 하려면 기반 클래스의 함수와 동일한 이름, 타입을 사용해야 함
오버라이드 된 경우 그 클래스의 함수 사용 안 된 경우 기반 클래스의 함수 사용 클래스.함수로 접근 시 해당 클래스의 함수 사용
오버라이드된 것을 명백히 하기 위해 함수의 헤더 마지막에  override 사용

-접근 제어
public, private, protected가 있음
클래스 D의 기반 클래스가 private인 경우 D만 기반 클래스의 public, protected 멤버 사용 가능
클래스 D의 기반 클래스가 protected인 경우 D, D에서 파생된 클래스만 기반 클래스의 public, protected 사용 가능
클래스 D의 기반 클래스가 public인 경우 누구나 사용 가능
friend (함수/클래스) 형식으로 사용 가능하며 private도 접근 가능함

-순수 가상 함수
추상 클래스: 추상적 개념을 나타내는 클래스, 기반 클래스로만 사용 가능
추상 클래스 생성 방식 => 
1. 생성자를 protected로 두기
2. 하나 이상의 함수를 순수 가상 함수로 만들기 virtual void f()=0 형식처럼 virtual, =0 사용
순수 가상 함수가 전부 오버라이드된 파생 클래스의 경우 객체 생성 가능 전부 안 된 경우 그 클래스도 추상 클래스임
순수 가상 함수를 포함하는 클래스의 경우 일반적으로 멤버를 포함하지 않으며(파생된 클래스에서 갖게 됨), 생성자도 없음(멤버가 없으므로 필요 없음)

-객체 지향 프로그래밍의 이점
인터페이스 상속: 기반 클래스를 입력으로 받는 함수에 대해 파생 클래스도 전달 가능
구현 상속: 파생된 클래스는 기반 클래스의 구현을 물려받아 그대로 사용 가능함
