1. context를 사용하지 않는다면 어떻게 되는가?
context를 사용하지 않을 경우 import된 c함수는 sv세계와 완전히 분리된 c 코드로 취급되면 sv의 상황을 모르므로 컴파일이 깨질 수 있다.
1-1 그렇다면 항상 context를 사용하면 되는거 아닌가?
context를 사용하면 sv 시뮬레이터가 문맥을 항상 기억하고 있어야 하므로 오버헤드가 발생해 함수 호출 비용이 커지는 단점이 있으므로 필요한 경우에만 사용하는 것이 좋다.
또한 c에서 svGetScope등의 함수를 사용하는 등 scope 핸들 관리가 필요해져 복잡성이 증가한다.

2. c에서 cout 또는 printf를 사용하는 대신 io_printf를 사용하는 이유는 무엇인가?
DPI-C에서 C 코드는 시뮬레이터 내부에서 실행되므로, 시뮬레이터 출력 시스템과 연동되는 io_printf()를 써야 한다. 전자를 사용할 경우 독립 실행 프로그램 기준이므로 출력이 
안 보이거나 시뮬레이터 로그와 섞이거나, 툴에 따라 아예 무시될 수도 있다.

3. new()와 new class_name()의 차이점은 무엇인가?
일반 생성자(정적 생성자)는 객체가 자동으로 생성될 때 호출되는 메소드이다, new()는 생성자가 호출되면서 객체가 초기화되지만 이 생성자만으로는 동적 메모리 할당을 하지 
않는다. (new()는 정적 생성자가 아닌 경우 이미 존재하는 객체에 값을 할당하거나 초기화할 때 사용)

동적할당을 사용하여 객체를 동적으로 생성할 때는 힙 메모리에서 객체가 할당되고, 그 후 생성자가 호출된다.
또한 동적 메모리 할당이 이루어지므로, 객체가 생성된 후 반드시 **delete**를 사용해 메모리 해제를 해야한다(필요한 경우).
(class s = new class()는 동적할당임)
배열을 초기화할 경우 각 요소를 초기화하려면 배열의 각 요소를 동적으로 할당해야 함

4. public, private, protected 함수의 차이점은 무엇인가?
각각의 함수의 차이점은 다음과 같다.
public 함수: public 키워드가 앞에 오며 외부에서 자유롭게 호출 가능
private 함수: private 키워드가 앞에 오며 클래스 외부에서 호출 불가(클래스 내에서만 호출 가능
protected 함수: 상속받은 클래스에서도 호출 가능 외부에서는 불가능
