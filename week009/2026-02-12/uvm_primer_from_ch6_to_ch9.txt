ch6 다형성
virtual 사용 -> sv에 피상적 변수 타입이 아닌 가리키는 객체를 확인하라고 알림 (없을 경을 경우 기반 클래스 함수 있으면서 동일한 시그니처를 가지는 함수가 존재하면 서브클래스)
추상 클래스는 베이스로만 사용 가능함( 인스턴스화 시도 시 런타임 에러)
pure virtual method의 경우 몸체는 가지지 않으며 파생된 클래스에서 반드시 오버라이드 해야 파생된 클래스 인스턴스화 가능

ch7. static method and variables
전역 변수의 경우 값이 쉽게 변경될 수 있으므로 문제가 될 수 있음
=> static 사용을 통해 정의, 사용, 유지하기 쉽게 만들기
static 변수가 클래스 내부에 있다면 이 변수는 인스턴스횟수에 관계 없이 하나의 복사본을 갖게 됨
static 메서드 -> 구현을 숨기고 이후 객체 사용을 쉽게 해줌(인터페이스를 제공해 객체를 사용하기 쉽게 해줌 다른 사람이 수정 불가능해 이후 수정이 쉬워짐), ::로 접근
static으로 가능하면 전역변수 말고 static 변수 사용

ch8. parameterized class definition
여러 타입에 대해 비슷한 구조를 가지는 클래스가 필요해 복사를 사용할 경우 메서드 추가 시 전부 해야해서 힘들며 코드가 길어짐) => 파라미터화 사용

ch9. 팩토리 패턴
프로그래밍 트릭을 디자인 패턴이라 부름
원래는 서로 다른 타입의 객체를 생성해야할 경우 코드를 수정해야 했으나 팩토리 패턴을 이용하면 문자열같은 데이터를 입력으로 받아 적절한 타입의 객체를 동적으로 생성 가능함
virtual로 선언됐으며 서브, 슈퍼클래스에서 모두 갖고 있는 메서드의 경우 다형성 사용이 가능하나 서브에만 있는 경우 컴파일 에러를 막기 위해 super 객체를 sub객체로 전환할 필요
있음 $cast 사용
팩토리를 이용해 UVM을 이용한 테스트벤치에서 테스트벤치 구성요소를 동적으로 생성 가능함
